### [SGLang v0.5.19 发布：新增多模型与推理优化](https://github.com/sgl-project/sglang/releases/tag/v0.5.19) ⭐️ 7.0/10

SGLang v0.5.19 已发布，集合来自 214 名贡献者的 786 个 PR。新支持 Qwen3.8、Qwen3.8-27B、dots3.note、Ling-3.0-flash/tiny、Spark2.5、MiniCPM-SALA、Granite 4.2、LongCat-Image-Edit 等模型，并新增 GLM-5.3、PaddleOCR-VL 等部署指南。性能与功能方面加入 beam search、DeepEP v2 的 --moe-a2a-backend deepep\_v2、LayerNorm 序列并行（--enable-layernorm-sp）、Hopper W4A8 MoE、Blackwell MLA 后端的 DCP、统一的 radix tree 默认缓存以及 AMD Lean attention。基准数据包括：LayerNorm SP 使 Qwen3-8B prefill 在 H100 上快 3.5%、在 B200 上快 5.6%；W4A8 MoE 让 DeepSeek-V4-Flash 输出吞吐提升约 12%；MI355X 上 lean attention 最高可提升 1.52 倍吞吐并降低 3.62 倍 token 间延迟。依赖同步升级为 FlashInfer 0.6.18、sgl-deep-ep 0.1.2、sgl-deep-gemm 0.1.7、mooncake 0.3.13，并新增 CUDA 13.4 Rubin 预览镜像及 ROCm 10 gfx942/gfx950/gfx1250 镜像。

github · Qiaolin-Yu · 9月5日 02:27

**「背景」** SGLang 是一个面向大语言模型的高性能开源推理与服务引擎，通过连续批处理、RadixAttention 缓存和多种后端优化来降低延迟与成本。此次常规主版本发布集中了社区在过去一段时间的大量功能与修复，v0.5.19 属于其持续迭代中的一次大规模聚合更新。

**「影响」** 对于使用 SGLang 部署 Qwen、GLM、DeepSeek、Kimi 等模型的团队，升级到 v0.5.19 能立即获得新增模型支持、默认缓存行为变化以及多项吞吐和延迟改进，但在启用 beam search 与既有投机解码、解聚、DP attention 或 HiCache 组合前需注意其尚不兼容的限制。

### [语言模型可声明自己的注意力范围](https://www.reddit.com/r/MachineLearning/comments/1w7sgf3/language_models_can_control_their_own_attention_r/) ⭐️ 7.0/10

一项名为“声明式注意力”（Declarative Attention, DA）的研究提出，让大语言模型在生成过程中显式声明需要关注的上下文区域，据此将解码模式划分为&lt;global&gt;（全上下文）、&lt;focus&gt;（特定区域）和&lt;local&gt;（仅最近输出），从而让推理引擎像解析工具调用一样跳过大部分 KV 缓存读取。研究者在 15 项长上下文任务上对 Gemma-4-31B 和 Qwen-3.6-27B 等现成模型进行零样本评估，结果显示解码期间需关注的 token 总量分别减少 52.0%和 31.1%，而准确率仅下降 1.27 个百分点和 2.75 个百分点，且下降幅度随模型规模增大而缩小。该方法与通过轻量代理分数预选相关 token 的外部评分方式不同，它直接利用模型自身对上下文相关性的判断，避免了每步 O\(N\)的附加开销；论文指出这为稀疏注意力开辟了新维度，未来结合训练的方法可能进一步提升效果。相关工作以 arXiv:2609.02737 形式发布，DOI 为 https://doi.org/10.48550/arXiv.2609.02737。

reddit · r/MachineLearning · /u/eigenlaplace · 9月5日 06:07

**「背景」** 现代大语言模型在生成每个 token 时，通常需要对整个上下文执行注意力计算，并将历史输入对应的键值缓存（KV cache）全部读入内存，这使得长上下文推理的每一步代价都随上下文长度线性增长。虽然模型实际往往只依赖上下文中极少量的关键 token，但现有预选相关 token 的方法仍需要额外扫描整个上下文以获得代理分数，因此无法从根本上消除线性成本。声明式注意力希望换个思路：既然模型自己可能知道哪些内容重要，不如让它在推理过程中直接声明需要关注的区域。

**「影响」** 对于部署长上下文大模型并进行大量解码的开发者，该方案提供了一种无需重新训练即可显著减少 KV 缓存读取量的零样本优化手段，可能降低长对话和长文档场景下的推理算力与内存开销；不过论文显示该优化目前仍伴随小幅准确率下降，实际效果需结合具体任务和模型规模验证。
