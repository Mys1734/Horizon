### [Kernel.org spends more CPU serving crawlers than git clones](https://simonwillison.net/2026/Sep/7/creepy-crawlies/) ⭐️ 7.0/10

Simon Willison highlights Konstantin Ryabitsev&\#x27;s report on git.kernel.org, the official Git repository for the Linux kernel. According to Ryabitsev, rendering commits for abusive scrapers now consumes more CPU cycles than all legitimate access, including git clones. Across five geo-distributed nodes, 14 CPU cores are continuously occupied solely rendering git commits as HTML for these crawlers. Willison connects this to his own concerns for Datasette, which serves many crawlable web pages, illustrating a growing infrastructure burden for public open-source services.

rss · Simon Willison · Sep 7, 23:08

**「Background」** git.kernel.org is the official Git hosting site for the Linux kernel, and in addition to serving git-aware operations like clones it renders commit pages as HTML for browsers and other HTTP clients. Konstantin Ryabitsev, a kernel.org administrator, has described how abusive crawlers—often associated with AI training/data collection—have become a major share of that web traffic. His report notes about 6 million daily requests for arbitrary commit pages, with roughly two-thirds blocked by an Anubis proof-of-work challenge but one-third getting through and consuming significant CPU across the five geo-distributed nodes.

**「Impact」** Maintainers of popular crawlable open-source infrastructure may need to budget computing resources specifically for scraper traffic, since git.kernel.org already devotes 14 CPU cores at any one time to this work.

### [417K-Parameter RNN Generates Bad Apple from a Single Initial State](https://www.reddit.com/r/MachineLearning/comments/1wa8rub/generating_bad_apple_autonomously_from_a_single/) ⭐️ 7.0/10

A Reddit user shared an open-source recurrent dynamical system that autonomously generates the entire Bad Apple video sequence, about 6,500 full-resolution grayscale frames, from a single initial state rather than requiring timestamp inputs. The inference model has 417,129 parameters \(~1.60 MB FP32\), consisting of a 16,640-parameter 4-gate LSTM-style recurrent transition with orthogonal initialization and a 400,361-parameter frame decoder using stage-wise bilinear upsampling and depthwise-separable convolutions. The system runs at more than 200 FPS on an RTX 4080 with about 17.2 MB peak active VRAM. To train the autonomous rollout, the author used learned latent teacher tables, progressive rollout horizon lengths from 2 to 512, state perturbation noise, second-difference acceleration regularization, and AdamW/Muon optimization with momentum scaling. Code, weights, and rollout analysis tools are available on GitHub under SEBADA321/BadAppleRNN.

reddit · r/MachineLearning · /u/SEBADA321 · Sep 8, 00:05

**「Background」** Recent work trained a SIREN MLP to map coordinates \(t, y, x\) to pixels, implicitly memorizing bad Apple as a coordinate function. This project instead explores whether a compact recurrent neural network can learn continuous latent temporal flow and produce the whole video in a closed loop from one fixed initial condition, without receiving timestamps during inference.

**「Impact」** The open-sourced model demonstrates that a highly compact recurrent architecture can learn long-term stable video generation from a single initial state, offering a concrete reference point for researchers studying autonomous dynamical systems and long-horizon sequence generation. The author notes the current decoder needs optimization and that the experimental process was not rigorously isolated, so effects of individual training techniques remain uncertain.

### [LLM-guided evolution improves 10 circle-packing benchmark solutions](https://www.reddit.com/r/MachineLearning/comments/1w9xlyi/llmguided_program_evolution_improves_10_bestknown/) ⭐️ 7.0/10

The author used an LLM to iteratively evolve an optimization algorithm rather than directly solving circle-packing instances. Starting from a simple seed solver, each proposed algorithmic change was guided by a scoreboard of results and prior attempt history, then scored by an independent verifier so only improvements were kept. On the Packomania csqv benchmark, this process improved the best-known sum-of-radii for 10 values of N from 101 to 114 by 2.4% to 5.4% within 15 iterations, at a total LLM cost of $27.72. Packomania independently accepted the results. The paper, code, solutions, and benchmark are publicly available at arxiv.org/abs/2609.05093, github.com/ucsandman/discovery-loop, and packomania.com/csqv/csqv.html.

reddit · r/MachineLearning · /u/SIGH\_I\_CALL · Sep 7, 16:54

**「Background」** Circle packing is a classical geometry optimization problem where circles are arranged inside a container without overlaps, and Packomania maintains well-known benchmark instances of such tasks. The csqv benchmark specifically asks for the maximum sum of radii of variable-radius circles placed in a unit square, and Packomania independently verifies candidate solutions, making its best-known records a standard point of comparison.

**「Impact」** Researchers working on the Packomania csqv instances for N=101-114 now have new independently verified best-known solutions and a concrete, low-cost example of LLM-guided program evolution for constrained optimization, though the method&\#x27;s broader applicability beyond this benchmark remains undemonstrated.

### [Deckard: a local-model Chrome extension for flagging AI text](https://seangoedecke.com/deckard/) ⭐️ 6.0/10

rss · Sean Goedecke · Sep 8, 00:00

**「Background」** Sean Goedecke wanted browser-wide, automatic checks for AI-written text instead of manually submitting suspicious passages to Pangram, a commercial detector he considers excellent but effectively alone in the field. Sending every page he reads to a third party seemed undesirable, so he benchmarked small open-source models to see whether they could run locally as a practical alternative.

**「Solution」** His benchmarks found the best small models caught only about 56% of AI-involved text while flagging roughly 2.5% of human text, far below Pangram&\#x27;s claimed 99.66% detection rate with a 0.004% false-positive rate. The author decided this was still useful: a low-confidence flag can prompt suspicion rather than prove AI use, without the privacy or cost of a remote service. He built Deckard, a Chrome extension that talks over native messaging to a locally running model on a Mac, using one of the benchmarked models. It consumes about 400 MB to 1.2 GB while active and disables itself after five idle minutes, and the author reports it marked known AI text such as YouTube&\#x27;s AI summaries and his own AI-generated snippets. He acknowledges Deckard is far worse than Pangram but says the lightweight background check is worthwhile for his own browsing.

**「Takeaway」** The author&\#x27;s central point is that local AI-text detection is already good enough to raise useful suspicion while browsing, and that building around small local models now is worthwhile because he expects them to improve by 2x or 10x. The practical payoff is continuous checking without sending every page to a remote service, even if today&\#x27;s local models are far behind commercial detectors.
