### [爬虫滥用消耗 git.kernel.org 大量 CPU，超过合法访问](https://simonwillison.net/2026/Sep/7/creepy-crawlies/) ⭐️ 7.0/10

Linux 内核官方仓库 git.kernel.org 的维护者 Konstantin Ryabitsev 报告称，恶意爬虫带来的“背景辐射”已变得非常严重：在 5 个地理分布式节点上，任意时刻都有 14 个 CPU 核心仅用于把 git 提交渲染成 HTML，其消耗的 CPU 周期已超过所有其他合法访问，包括 git clone。Simon Willison 引用并讨论了这一情况，并表示同样面向大量可抓取网页的 Datasette 项目也有类似担忧。该内容经 Hacker News 传播，但没有提供爬虫身份或具体缓解方案的更多技术细节。

rss · Simon Willison · 9月7日 23:08

**「背景」** git.kernel.org 是 Linux 内核的官方 Git 仓库托管站点，既提供 git clone/pull 等版本操作，也提供网页界面供用户浏览提交记录。Konstantin Ryabitsev 长期负责维护 kernel.org 基础设施，并在 people.kernel.org 上撰文披露了 AI 爬虫对服务器造成的具体影响。文章中提到的 Anubis 挑战是此前已部署的、用于拦截滥用爬虫的验证机制。

**「影响」** 对运行大型公开 Web 基础设施的维护者而言，这直接意味着需要为爬虫流量预留可观的算力资源：git.kernel.org 目前实时占用 14 个 CPU 核心持续渲染 HTML。该现象也表明，爬虫流量与合法访问之间的资源竞争已成为开源基础设施需要认真面对的实际运维负担。

### [417k 参数 RNN 从单初始状态自主生成 Bad Apple](https://www.reddit.com/r/MachineLearning/comments/1wa8rub/generating_bad_apple_autonomously_from_a_single/) ⭐️ 7.0/10

在 Reddit 的 r/MachineLearning 上，/u/SEBADA321 发布了一个小型循环动力学系统，可用约 417,129 个参数（FP32 下约 1.60 MB）从单一的 64 维初始向量\(h\_0, c\_0\)闭环自主生成整段 Bad Apple 视频，无需逐帧的时间戳输入。系统包含 16,640 参数的四门 LSTM 式循环转移和 400,361 参数的帧解码器，推理时在 RTX 4080 上能以超过 200 FPS 运行，峰值显存约 17.2 MB，输出为 384x512 灰度帧。训练采用可丢弃的潜伏教师表、展开长度从 2 逐步翻倍到 512 的课程、状态扰动噪声、二阶差分加速正则化以及 Muon/AdamW 混合优化等技巧，以应对数千步递推造成的梯度消失、爆炸和误差累积问题。作者已公开代码、权重与分析工具，并指出最低训练损失并不保证最长的自主生成稳定性。

reddit · r/MachineLearning · /u/SEBADA321 · 9月8日 00:05

**「背景」** 此前有工作用 SIREN MLP 把 Bad Apple 的坐标\(t, y, x\)映射到像素值来隐式记忆视频。本项则将思路改为让循环网络在潜伏空间学习连续时间流，从单个初始状态自主展开生成整段视频，属于对紧凑循环系统与视频生成结合的小众技术探索。

**「影响」** 这项开源工作为研究小参数循环网络在数千步闭环视频生成中的稳定性训练提供了一个可复现的参考实现和基线数据，尤其展示了即使循环部分只有约 16k 参数，也能通过噪声注入和加速度正则化来维持长时间自主展开。

### [LLM 引导的程序演化改进圆填充最优解](https://www.reddit.com/r/MachineLearning/comments/1w9xlyi/llmguided_program_evolution_improves_10_bestknown/) ⭐️ 7.0/10

一位研究者利用 LLM 引导的迭代式程序演化方法改进圆填充问题的求解算法，而非直接求解布局。该方法从简单种子求解器出发，由 LLM 依据结果记分板与尝试历史提出算法修改，并用独立验证器评估候选方案。在 Packomania csqv 基准上，该方法将 N=101 至 114 中的 10 个实例的最佳已知半径和提高了 2.4%至 5.4%，仅用 15 次迭代，LLM 总成本为 27.72 美元。Packomania 已独立接受这些结果，论文与代码分别见 arxiv.org/abs/2609.05093 与 github.com/ucsandman/discovery-loop。

reddit · r/MachineLearning · /u/SIGH\_I\_CALL · 9月7日 16:54

**「背景」** Packomania 是一个收录圆填充问题最佳已知解或公开挑战的基准资源库；其中 csqv 变体要求在单位正方形内放置可变半径的圆并使半径总和最大化。该帖所述方法并非让大语言模型直接给出打包布局，而是从简单求解器出发，通过 LLM 迭代建议算法改动，并由独立验证器筛选改进。

**「影响」** 该成果使 Packomania 基准中相关实例的官方最佳记录得到更新，并为 LLM 引导的程序演化在数值优化基准上提供了一个可复现的低成本样例。

### [在浏览器里用本地模型自动检测 AI 文本](https://seangoedecke.com/deckard/) ⭐️ 6.0/10

rss · Sean Goedecke · 9月8日 00:00

**「背景」** 作者认为自动化 AI 文本检测是个缺乏竞争的领域，目前主要依赖商业服务 Pangram，但把浏览器里看到的每段文本都发送给第三方既花钱又让他有所顾虑。他希望有一个能在后台自动扫描网页、同时尊重隐私的本地方案。

**「方案」** 作者先对一批小型开源检测模型做了自己的基准测试，结果显示它们远比 Pangram 差：被误判为 AI 的人类文本约 2%，能抓到的 AI 相关文本在 19%到 56%之间。不过作者认为，这些模型足以用在“感到可疑”而非“实锤”的用途上。于是他通过“vibe coding”方式构建了 Chrome 扩展 Deckard：扩展直接通过 native messaging 启动并对话本地模型，无需本地 Web 服务器，运行时占约 400MB 到 1.2GB 内存，闲置五分钟会自动关闭。Deckard 能成功标出 YouTube 内置 AI 摘要和他自己文章里的 AI 片段，作者表示在日常使用中没有感觉到发热或续航下降。他也坦承它“远远不如 Pangram”，不比未来几年可能出现的新工具，但已打算自己长期使用；一旦本地小型模型变得更好，就能直接换掉底层模型。基准测试的具体方法没有披露，作者把相关功劳部分归给了 AI 助手 Astra。

**「启示」** 作者的核心结论是：在检测能力尚弱的今天，早期搭建这样一套本地检测工具仍然有价值，因为 AI 检测本地会随模型进步而改善，惯性和早期投入能让自己迅速受益于两倍或十倍更好的模型。
