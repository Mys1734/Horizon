### [Point Density, Not Architecture, Was the Bottleneck for Radar-Only 5-Class Classifier](https://www.reddit.com/r/MachineLearning/comments/1w934ew/point_density_not_architecture_was_the_bottleneck/) ⭐️ 7.0/10

A radar signal processing engineer reports that increasing points per instance from 1 to 5 roughly doubled macro F1 from 0.381 to 0.764 for a 5-class radar-only classifier on RadarScenes, while architecture and feature changes stayed within measured noise. The classifier used per-instance histogram encoding into a 3-layer MLP, with classes car, large\_vehicle, two\_wheeler, pedestrian, and pedestrian\_group. Sparse points hurt velocity-spread and size signatures: large\_vehicle F1 was 0.037 at one point per instance versus 0.995 with 11 or more points, and sparse two-wheelers and pedestrians collapsed into similar near-zero-velocity signatures. Wider/deeper networks, alternative feature encodings, and different bin edges did not improve results; swapping histograms for explicit mean/median/std statistics slightly hurt performance \(0.658 vs 0.686 baseline\), with pedestrian F1 falling outside its class-specific noise floor. Data caveats include naturalistic class imbalance, merged two-wheeler speed regimes, and a tracked two-wheeler quirk that can bias cross-validation splits.

reddit · r/MachineLearning · /u/bruno\_pinto90 · Sep 6, 17:55

**「Context」** RadarScenes is a large-scale automotive radar point cloud dataset containing over 7000 manually labeled road users, with point-wise class labels and track IDs for individual objects across four series radar sensors. It provides naturalistic, real-world driving data commonly used for radar-only perception tasks such as object classification.

**「Impact」** Practitioners working on radar-only object classification should prioritize increasing point density per object rather than investing in more complex architectures, while also accounting for sparse-class confusion and split-level biases during evaluation.
